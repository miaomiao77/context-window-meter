# 2.2.0：可比较的历史文本分词

用于自己的触顶样本：同一版本、同一编码，点「扫描当前对话」，等到「接口历史已读完」或「已核对返回分支父链」。只拿完成结果画线。记录来源类型、是否验证分支、文本 token、未计量消息数；无需保存聊天正文。2.1.x 的启发式读数与本版不可直接比较。没有官方剩余容量推断。

手动读取时，每条消息提取已识别的文本，保留有序 parts 的真实重复；相邻字段用换行分隔，同一消息的正文镜像不重复加入，相同文本在不同消息中仍然计数。以 o200k_base 对各条正文分别按普通文本编码后求和。附件、不可见的服务端输入和消息封装 token 不在内；不同模型实际使用的编码和输入可能不同。页面被动观察仍是便宜的局部字符估算，不能作校准点。消息数组不臆造父链，也不展开 versions。

遇到可恢复的分段预算（时长、总字节、页数）、取消、超时等：在同一标签页点击「从断点继续扫描」。保留已成功合并的页，复查首页和断点页的内容签名及游标再向前读，并在结束复查首页。硬性单页字节/消息总量限制不会循环重试。页面刷新、导航、编辑、发送、分支变化或不一致会使结果需要重新扫描。不是服务端原子快照。

分词器由锁定的 gpt-tokenizer 4.1.2 在构建时打包；运行时不连接词表服务，缓存合并片段的功能关闭。词表 SHA256 与 tiktoken 的 o200k_base 参考值一致（446a9538cb6c348e3516120d7c08b09f57c36495e2acfffe59a5bf8b0cfb1a2d）。见 licenses/。

验收：中文、算式、日文、emoji、特殊标记字面值、代码与 Python tiktoken 的 encode_ordinary 对照；仓库脱敏样本父链全部 251 条逐条一致，共 69,354 token。跨页重叠、分段续扫、网络中断、边界页/首页被改有离线回归。模拟并非对真实账号历史覆盖的证明。

开发分支分别记录分页起点、首页复核和分支父链。数组页必须以当前节点结尾；树的父链必须连至显式根。无重叠的相邻数组页无法独立证明服务端没有跳页。诊断按从新到旧的请求顺序编号，token 归到消息首次出现的页；去重和分支过滤后各页之和等于小计。首页及断点复查不重复计入。界面隐藏文本、工具输出按已返回的文本计量；不会展开其他版本或附件对象，明确标记的内嵌媒体数据串会跳过。无标记的文本编码无法可靠识别。
